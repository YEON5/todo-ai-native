## 1. 배경

현재 앱은 React 프론트엔드만 있고, 할 일 데이터는 브라우저의 React 상태에만 저장됩니다. 그래서 새로고침하면 모든 할 일이 사라집니다. 이번 단계의 목표는 같은 화면과 기능을 유지하면서 FastAPI와 Supabase로 데이터를 저장하고, Vercel에 배포할 수 있게 하는 것입니다.

## 2. 목표와 범위

**목표**
- 할 일을 추가·조회·수정·완료·삭제할 수 있다.
- 새로고침하거나 서버를 재시작해도 할 일이 남아 있다.
- 지금의 UI, 키보드 접근성, 반응형 동작을 그대로 유지한다.

**이번 범위에 포함하지 않는 것 (Out of Scope)**
- 로그인과 사용자별 할 일 분리. 모든 사용자가 같은 목록을 공유하는 단일 목록 MVP입니다. → [spec-review.md](spec-review.md) R-06 참고
- 카테고리, 우선순위, 필터, 정렬 변경. 이후 기능 확장 단계에서 다룹니다. (마감일은 v0.2에서 FR-009로 범위에 포함)
- 마감일의 시간 지정, 알림, 마감일 순 정렬, 기한 지남 강조 표시
- 드래그로 순서 바꾸기, 여러 개 한 번에 삭제하기

## 3. 사용자

할 일을 빠르게 적고 오늘 얼마나 끝냈는지 확인하려는 개인 사용자입니다. 데스크톱과 휴대폰에서 모두 쓰며, 키보드만으로도 쓸 수 있어야 합니다.

## 4. 기능 요구사항 (FR)

| ID | 기능 | 설명 | 현재 상태 |
| --- | --- | --- | --- |
| FR-001 | 할 일 생성 | 입력창에 제목을 적고 추가 버튼 또는 Enter로 목록 맨 아래에 추가한다. 앞뒤 공백은 제거하고, 비어 있으면 추가하지 않는다. | 구현됨 (In-Memory) |
| FR-002 | 목록 조회 | 앱을 열면 저장된 할 일을 생성 순서(오래된 것부터)로 보여준다. 할 일이 없으면 빈 목록 안내를 보여준다. | 구현됨 (In-Memory) |
| FR-003 | 제목 수정 | 수정 버튼으로 제목을 고친다. Enter는 저장, Esc는 취소다. 비어 있는 제목으로는 저장할 수 없다. | 구현됨 (In-Memory) |
| FR-004 | 완료 상태 변경 | 체크박스로 완료/미완료를 바꾼다. 완료된 할 일은 취소선과 흐린 카드로 표시한다. | 구현됨 (In-Memory) |
| FR-005 | 삭제 | 삭제 버튼으로 할 일을 즉시 삭제한다. 확인 창은 띄우지 않는다. | 구현됨 (In-Memory) |
| FR-006 | 완료율 표시 | 전체 대비 완료 비율(%)과 "N개 중 M개 완료" 문구, 할 일 하나당 한 칸인 진행 막대를 보여준다. | 구현됨 |
| FR-007 | 데이터 영속성 | FR-001~005, FR-009의 결과가 서버(DB)에 저장되어 새로고침·서버 재시작 후에도 유지된다. | 일부 구현 (새로고침은 유지, 서버 재시작 시 유실. Supabase 단계에서 완료) |
| FR-008 | 로딩·오류 표시 | 목록을 불러오는 중에는 로딩 상태를, 서버 요청이 실패하면 무엇이 실패했는지와 다시 시도하는 방법을 보여준다. 실패한 변경은 화면에 반영하지 않는다. | 구현됨 |
| FR-009 | 마감일 등록·수정 | 할 일을 추가할 때 마감일(날짜, 선택)을 함께 정할 수 있다. 편집 화면에서 마감일을 바꾸거나 지울 수 있다. 마감일이 있으면 카드에 날짜와 요일을 보여준다. 지난 날짜도 허용한다. 시간은 저장하지 않는다. | 구현됨 (In-Memory. DB 컬럼은 Supabase 단계 TASK-907) |

## 5. 비기능 요구사항 (NFR)

| ID | 분류 | 요구사항 |
| --- | --- | --- |
| NFR-001 | 접근성 | 모든 기능을 키보드만으로 쓸 수 있다. 포커스는 3px 앰버 외곽선으로 항상 보인다. 삭제 후·편집 후 포커스 이동 규칙을 유지한다([CLAUDE.md](../CLAUDE.md) "접근성과 포커스"). |
| NFR-002 | 반응형 | 너비 360px 이상에서 가로 스크롤 없이 쓸 수 있고, 터치 대상은 40px 이상이다. |
| NFR-003 | 디자인 일관성 | 색상·폰트는 `index.css`의 토큰만 쓰고, 외부 UI 라이브러리를 쓰지 않는다. |
| NFR-004 | 보안 | Supabase 서버 키는 백엔드 환경 변수로만 쓰고 저장소에 커밋하지 않는다. `todos` 테이블은 RLS를 켜서 공개 클라이언트가 직접 접근하지 못하게 한다. |
| NFR-005 | API 호환성 | `/api/todos` 경로와 응답 형식은 한 번 정하면 저장소를 In-Memory에서 Supabase로 바꿔도 그대로 유지한다. |
| NFR-006 | 테스트 | 백엔드는 pytest로 FR-001~005와 오류 경로를 검증하고, 프론트는 빌드·린트를 통과한다. 결과는 PASS/FAIL/SKIP으로 보고한다. |

## 6. 제약과 가정

- 제목 길이는 공백 제거 후 1~200자로 제한한다. → R-04
- 동시에 여러 사람이 편집하는 경우의 충돌 처리는 하지 않는다. 마지막 요청이 반영된다.
- 서버 응답을 받은 뒤에 화면을 바꾼다(비관적 갱신). → R-08
